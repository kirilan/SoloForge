no JDK and no Android SDK. **None of it has ever been compiled.** `assembleDebug`,

## 3. Where this most likely breaks

These are guesses, not known failures. Both are in code that no static check could cover.

**`AnalysisModelPicker` in `ui/settings/SettingsScreen.kt`.** New Compose imports were added by
hand: `androidx.compose.material3.RadioButton`, `androidx.compose.foundation.clickable`, and
`java.util.Locale`. If `String.format(Locale.US, ...)` doesn't resolve, the Kotlin stdlib
extension is `kotlin.text.String.Companion.format` — check the import isn't shadowed by the
existing `androidx.compose.ui.platform.LocalLocale`.

**`io.ktor.http.content.TextContent` in `network/OpenRouterClientTest.kt`.** Chosen for Ktor
2.3.13 (`gradle/libs.versions.toml`), where the golden tests cast `request.body` to read the
encoded request. That class moved between Ktor major versions. If it fails, the alternatives are
`io.ktor.content.TextContent` (1.x) or reading the body via `OutgoingContent` instead.

**`AnalysisConfig` is a `data class` with a computed `isMeasured` in its body** — fine in Kotlin,
but if the KSP/Hilt pass complains, that's the first novel construct to look at.

## 5. Manual checks the tests can't make

Do these on a device or emulator after `assembleDebug`:

- [ ] Switch between all four rows; analyze a photo on each; confirm the saved entry's
      `modelUsed` records the id you'd expect.
- [ ] **Retry button visibility** — present on *Fastest* and *Balanced*, **absent** on
      *Open-weight* and *Most accurate*. This is the single most important manual check: it is
      the whole point of per-row escalation, and nothing automated covers it.
- [ ] Select *Advanced*, enter a junk id like `vendor/does-not-exist`, analyze. The failure must
      surface the **raw** provider message (per the raw-errors convention in `CLAUDE.md`), not a
      friendly paraphrase.
- [ ] Clear the Advanced id to blank; confirm analysis falls back to the default rather than
      requesting an empty model.
- [ ] Toggle AI off; confirm the whole picker disappears with the rest of the AI section.
- [ ] Export a backup, wipe data, import it; confirm the chosen row survives.
- [ ] Import a **pre-0.7.0** backup; it must still decode (both new fields are defaulted).

## 6. If the build changes any behaviour

Any fix that touches the request body, the prompt, temperature, image prep, or the schema means
the eval numbers no longer describe the app, and `FoodAnalysisModels` is then lying to users.
Re-run all four rows before tagging:

```powershell
python tools\food_eval\run_eval.py --model google/gemini-3.1-flash-lite
```

…and the same for `google/gemini-3.7-flash`, `qwen/qwen3-vl-32b-instruct`, and
`google/gemini-3.1-pro-preview`. No `--reasoning`, no `--max-tokens` — a flagged run is not the
app's request shape. Update `FoodAnalysisModels` if anything moved.

The current labels come from a clean 2026-08-29 run: 44 cases, all four rows, uncapped,
unflagged, zero call failures.

## 7. Only after everything is green

Version bump and changelog are **already done** (`versionCode` 13, `versionName` 0.7.0,
`fastlane/metadata/android/en-US/changelogs/13.txt`). Remaining release steps, in order:

1. Merge `food-eval-model-sweep` into `main`.
2. **Network monitor pass — required for this release.** Phase 0 changed the request body and the
   free-text row means the app can now send a model id we have never sent. Confirm `openrouter.ai`
   is still the only outbound host and that AI-off produces zero traffic.
3. Tag `v0.7.0` and push. **The tag push IS the F-Droid release** — do not push it until 1 and 2
   are done.
4. GitHub release with a debug-signed `SoloForge-0.7.0-debug.apk`.
5. Play: `.\gradlew.bat bundleRelease`, then `python tools\play_release.py --dry-run` first.
