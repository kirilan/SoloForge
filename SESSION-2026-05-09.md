## What got built (in chronological order)

### Phase 0 + 1 — environment & skeleton
- Android Studio Ladybug guidance for the user (no dev env existed).
- Gradle scaffolding: `settings.gradle.kts`, `build.gradle.kts`, `app/build.gradle.kts`, `gradle/libs.versions.toml`, `gradle.properties`, `proguard-rules.pro`.
- AndroidManifest with permissions for `INTERNET`, `CAMERA`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE`, `VIBRATE`. `<application>` with `SpicyCrabApp` (Hilt) and `MainActivity`.
- Material 3 theme (`SeedGreen` seed, dynamic color on Android 12+, oversized display typography).
- Bottom-nav skeleton with 6 tabs: Home / Fast / Food / Weight / Workout / Settings. Routes always registered; bottom-bar items filtered by tab visibility setting.
- Resolved early build issues: Android 15 / API 35 compileSdk bump, Room `fallbackToDestructiveMigration()` no-arg signature, `KeyboardOptions` import path (`androidx.compose.foundation.text.KeyboardOptions`), `ExposedDropdownMenu` is a member of `ExposedDropdownMenuBoxScope`.

### Phase 2 — Fasting timer
- `FastingMode` enum: 16:8, 18:6, 20:4, 36h. Each carries `fastHours` + `eatingWindowHours`.
- Room entity `FastSession`. DAO with insert/update/delete + observe-active + observe-all.
- `FastingRepository` with start/stop, scheduling reminders via `ReminderScheduler`.
- `FastingNotificationService` — proper foreground service (`specialUse`) with 30s ticker and persistent live notification.
- `ReminderScheduler` (WorkManager `OneTimeWorkRequest`):
  - **"Almost there"** encouragement 1h before fast ends (5 randomized messages).
  - **"Eating window closing"** 1h before window ends, scheduled when a completed fast ends.
  - Cancelled when user takes opposite action.
- `FastingScreen` with Canvas-drawn animated progress ring (`ProgressRing.kt`), mode-picker chips, Start/End/Cancel buttons.
- **Edit/delete added later in the session**: tap a history row → `EditFastSheet` with mode chips + start/end text fields (`yyyy-MM-dd HH:mm`) + delete. Mode change recomputes target + completion. Active fasts get an "Edit start" button + Cancel.

### Phase 3 — AI calorie counter
- `SecureKeyStore`: EncryptedSharedPreferences (AES256_GCM) for the OpenRouter API key. Excluded from auto-backup (`backup_rules.xml`, `data_extraction_rules.xml`).
- `SettingsRepo` (DataStore preferences): selected model, export folder URI, save-photo toggle, weight unit, daily macro goals, weekly weigh-in time, default fasting mode, reminder toggles, **tab visibility flags**.
- `ApprovedModels.ALL` (vetted via OpenRouter `/api/v1/models`):
  ```
  google/gemini-2.5-flash       # default
  google/gemma-4-31b-it
  anthropic/claude-haiku-4.5
  openai/gpt-4o-mini
  ```
  - Stored values that aren't in `ALL` auto-fall-back to `DEFAULT` on read (graceful migration).
- `OpenRouterClient` (Ktor + OkHttp engine):
  - Multimodal `chat/completions` request with `image_url` data-URL.
  - `response_format: json_object`, system prompt enforces strict JSON.
  - Strips `\`\`\`json` fences if a model emits them.
  - Headers: `HTTP-Referer: app://com.kbul.spicycrab`, `X-Title: Spicy Crab`.
- `ImageUtils`: EXIF-aware rotation, resize to 1024px long edge, JPEG 85%, base64.
- Room entity `FoodEntry` with `lastModifiedEpoch` (added later when edit was implemented).
- `FoodRepository`:
  - `analyze(imageFile, comment)` → `NutritionEstimate`.
  - `save(estimate, comment, imageFile)` — copies image to filesDir if `savePhotoLocally`, persists, appends CSV.
  - `update(updated)` — bumps `lastModifiedEpoch`, **appends a new CSV row** with same `entry_id` (append-only audit log).
  - `addManual(draft)` — manual-entry path, sets `model="manual"`, `confidence="user"`, `imagePath=null`.
- `CsvExporter` (SAF-based, `ACTION_OPEN_DOCUMENT_TREE` with persisted URI permissions):
  - `food_log.csv` columns: `entry_id, timestamp_iso, last_modified_iso, item_name, grams, kcal, protein_g, carbs_g, fat_g, fiber_g, comment, model, confidence`.
  - `weight_log.csv` columns: `timestamp_iso, weight_kg, note`.
  - `workout_log.csv` columns: `id, mode, start_iso, end_iso, last_modified_iso, total_seconds, interval_seconds, exercise_seconds, rest_seconds, notes`.
  - `appendFoodEntry / appendWeightRow / appendWorkoutEntry` — auto-append on save/edit.
  - `rewriteAll(...)` — full rewrite, used by Settings → "Export all data".
- UI:
  - **CaptureScreen** — CameraX preview + capture, runtime permission handling.
  - **AnalyzeScreen** — image preview, comment field, Analyze button, editable result form with confidence badge, Save/Discard. Re-analyze with current comment when an estimate exists. **"Scale by grams…"** button proportionally rescales all macros + kcal.
  - **EditFoodSheet** — tap any food row to edit; same fields + Re-analyze (only if `imagePath` non-null) + Delete. Reanalysis driven through a VM `EditingState` (`isReanalyzing`, `reanalyzeStamp` to refresh draft).
  - **ManualFoodSheet** — small secondary FAB on the food list opens this. Same form fields as the estimate review, no AI. Save requires item name + non-zero calories.
  - Food row shows "· edited" when `lastModifiedEpoch > timestampEpoch`.

### Workout timer (most recent feature)
- `WorkoutMode` enum: SIMPLE, INTERVAL, EXERCISE_REST.
- `WorkoutPhase` enum: PAUSED, EXERCISE, REST.
- `WorkoutStateHolder` (singleton) — in-memory `ActiveWorkoutState` with `activeSeconds(now)` and `currentPhaseElapsedSeconds(now)` extension helpers (phase-aware: paused time excluded).
- Room entity `WorkoutSession`, DAO, DB v4 (destructive migration on).
- `WorkoutNotificationService` (foreground, `specialUse`):
  - Owns the live state machine. Receives intents: START, TOGGLE_PHASE, TOGGLE_PAUSE, PAUSE, STOP.
  - Ticking notification updates every 1s.
  - **Interval mode** beep loop: starts with a confirmation beep, then loops aligned to `(active_total % intervalMs)` so beeps stay on the boundary even after pauses.
  - **Audio policy** (respects ringer mode):
    - **Normal**: interval = `STREAM_MUSIC` vol 80, `TONE_CDMA_HIGH_L` 500ms. Phase-change = 60ms haptic + soft `TONE_PROP_ACK` vol 35.
    - **Vibrate**: interval = 250ms vibration. Phase-change = 60ms haptic.
    - **Silent**: nothing.
  - On STOP: persists `endEpoch`, `totalSeconds = activeSeconds(now)` (paused time NOT counted), `exerciseSeconds`, `restSeconds`, `lastModifiedEpoch`. Repository appends to CSV.
- `WorkoutRepository` — start, togglePhase, togglePause, pause, stop (persists + appends CSV), update, delete, observeForDay.
- `WorkoutViewModel`, `WorkoutScreen` with three mode-specific cards:
  - **SimpleActiveCard**: big total timer, "Running" / "Paused" label, Pause/Resume button + End.
  - **IntervalActiveCard**: big counter resets each interval, smaller "Total: hh:mm:ss" and "N intervals completed" below.
  - **ExerciseRestActiveCard**: card tinted by phase color, huge `WORKING` / `RESTING` / `PAUSED` label, big counter = current phase elapsed, Exercise/Rest/Total stats row, large toggle button.
- `EditWorkoutSheet` — edit total/exercise/rest seconds + notes + delete.
- Screen `keepScreenOn` while INTERVAL or EXERCISE_REST is active.
- **Calorie bonus**: `bonus_kcal = round(250 * today_workout_seconds / 3600)` added to displayed kcal goal on Home's nutrition tile, with "+N kcal from training" line.

## Conventions established (also in CLAUDE.md)

- Single-activity Compose with bottom nav. Sub-flows live in sealed `UiMode` enums inside feature ViewModels, **not** as nav routes.
- ViewModels expose `StateFlow` via `stateIn(viewModelScope, WhileSubscribed(5_000), initial)`.
- Repositories, DAOs, network clients are `@Singleton` with constructor DI.
- Source of truth for active sessions = the row in Room (fasting) or the singleton `WorkoutStateHolder` (workout).
- Reminders are state-driven, not time-of-day-driven (schedule on lifecycle event, cancel on opposite event).
- CSV exports auto-append on save when an export folder is set; edits append a new row with the same `entry_id` and updated `last_modified_iso` so external readers can take the latest per id.
- Privacy: only outbound host is `openrouter.ai`, only when analyzing food. No analytics, no crash reporters.
